| 항목 | 내용 |
|---|---|
| 문서 ID | SI-01 |
| 대상 | `jgjoe/Build-Your-Health` `master@c66c1f0` (`BuildYourHealth/src/main`) |
| 작성일 | 2026-10-02 |
| 작성 방법 | 소스 전수 열람(Java 9개, JSP 54개, SQL 9개, `web.xml`) + 로컬 재현 환경 실행 결과(`03_테스트시나리오.md`) |

이 문서는 2024년 2학기 교과 프로젝트로 만든 시스템을 이관 대상 "현행 시스템"으로 보고 다시 읽은 결과다. 만든 사람의 기억이 아니라 코드와 실행 결과만 근거로 적는다.

## 1. 시스템 개요

| 항목 | 내용 |
|---|---|

## 3. 데이터 구조

DDL 출처: `webapp/resources/sql/*.sql` [코드]. 시드 데이터는 `insert.sql`(상품 1건, 콘텐츠 6건)뿐이다.

| 테이블 | 주요 컬럼 | PK | 참조(FK) | 비고 |
|---|---|---|---|---|
| `member` | id, password, name, gender, birth, email, phone, address, age_group, water_intake, sleep_hours, remaining_water, remaining_sleep, reg_date | id `VARCHAR(50)` | - | 비밀번호 `VARCHAR(50)` 평문. 권장량·남은 양을 회원 행에 함께 둠 |
| `user_records` | record_id, user_id, consumed_water, consumed_sleep, record_date | record_id | user_id → member.id (CASCADE 없음) | 차감은 음수 행으로 기록 |
| `product` | product_id, product_name, regular_price, discount_price, manufacturer, shipping_info, image_file, product_options(TEXT, JSON), arrival_date | product_id `VARCHAR(10)` | - | |
| `orders` | order_id, user_id, order_date, delivery_date, total_price, shipping_address, shipping_zipcode | order_id | user_id → member.id ON DELETE CASCADE | 받는 사람 이름·국가 컬럼은 없음(쿠키에만 존재) |
| `order_items` | item_id, order_id, product_id, quantity, price | item_id | order_id → orders ON DELETE CASCADE, product_id → product ON DELETE CASCADE | price는 주문 시점 할인가 |
| `reviews` | review_id, product_id, user_id, review, created_at | review_id | product_id → product (CASCADE 없음) | user_id에 FK 없음 |
| `board` | num, id, name, subject, content, regist_day, hit, ip, image_file_name | num | - | 작성자 id에 FK 없음 |
| `CONTENTS` | id, video_url, title | id | - | |

**관계 요약**: 회원 1—N 주문 1—N 주문상품 N—1 상품, 상품 1—N 리뷰, 회원 1—N 건강 기록. 게시판·리뷰 작성자는 FK 없이 ID 문자열만 저장한다.

**인덱스**: PK와 FK에 자동 생성되는 인덱스 외에 정의된 인덱스가 없다 [코드]. 조회 조건으로 쓰이는 `reviews.product_id`·`orders.user_id`·`user_records.user_id`는 FK라 InnoDB가 인덱스를 만든다. 게시판 검색은 `LIKE '%검색어%'`라 인덱스를 쓸 수 없는 형태다.

**테이블명 대소문자**: DDL은 `member`·`user_records`, 쿼리는 `MEMBER`·`USER_RECORDS`·`CONTENTS`를 섞어 쓴다. 대소문자를 구분하지 않는 Windows MySQL에서 개발된 상태이며, Linux MySQL 기본 설정(`lower_case_table_names=0`)에서는 그대로 동작하지 않는다 [코드]. 재현 환경은 `lower_case_table_names=1`로 맞췄다.

## 4. 처리 흐름

### 4.1 로그인과 권한 검사

1. `processLoginMember.jsp`가 JSTL `sql:query`로 `SELECT * FROM MEMBER WHERE ID = ? AND password = ?`를 실행한다.
2. 행이 있으면 `sessionId`(ID)·`sessionName`(이름)을 세션에 넣고 `welcome.jsp?msg=2`로 이동한다.
3. 이후 권한 검사는 **필터가 아니라 각 JSP가 개별로** 한다. 회원 기능은 `session.getAttribute("sessionId") != null`, 관리자 기능은 `"admin".equals(sessionId)`를 확인한다. 두 로깅 필터는 권한에 관여하지 않는다.
4. 메뉴(`templates/menu.jsp`)는 세션 상태에 따라 링크를 숨기지만, 2절에 "서버 검사 없음"으로 표시한 처리 JSP는 URL을 직접 호출하면 실행된다.

### 4.2 주문 확정 (AS-F-040 → 042)

1. `processShippingInfo.jsp`: 세션 로그인 확인 → 배송일 형식 검증 → 입력값을 쿠키 6개에 저장 → `orderConfirmation.jsp`.
2. `orderConfirmation.jsp`: 쿠키와 세션 장바구니로 확인 화면 표시.
3. `thankCustomer.jsp`(GET): 세션 장바구니 합계 계산 → 한 커넥션에서 `orders` INSERT(생성 키 반환) → `order_items` 배치 INSERT → 예외는 로그 출력 후 진행 → 장바구니 세션 삭제 → 감사 화면.
4. 커넥션은 자동 커밋 상태 그대로이며 `commit`·`rollback`·`setAutoCommit` 호출이 저장소 전체에 없다 [코드].

### 4.3 건강 기록 (AS-F-011)

1. `MEMBER`에서 권장량 조회 → `USER_RECORDS`에서 해당 회원 전체 기록 합계 조회(날짜 조건 없음).
2. 합계 + 입력값이 권장량을 넘으면 경고 후 종료.
3. `USER_RECORDS` INSERT → `MEMBER.remaining_*` = 권장량 − 새 합계로 UPDATE → `welcome.jsp`.
4. 두 쓰기는 각각 자동 커밋된다.

### 4.4 게시판 목록 (AS-F-060)

1. `BoardController`가 `pageNum`·`items`·`text`를 받아 `BoardDAO.getListCount()`와 `getBoardList()`를 호출한다.
2. 검색 조건이 있으면 `"... where " + items + " like '%" + text + "%'"`로 **문자열을 이어 붙여** SQL을 만든다.
3. 목록 SQL에는 `LIMIT`이 없다. 스크롤 가능한 결과 집합으로 전체 행을 받은 뒤 `rs.absolute(시작 위치)`로 이동해 5건을 읽는다.
4. 결과를 request 속성으로 `board/list.jsp`에 forward한다.

## 5. 현행 제약·문제점

당시는 교과 과제 범위에서 기능 완성을 우선했고 단일 개발자·로컬 실행을 전제로 했다. 아래는 그 전제를 벗어나 운영하거나 이관할 때 걸리는 지점이다. 요구사항정의서는 이 번호를 근거로 참조한다.

| 번호 | 영역 | 내용 | 근거 |

## 부록. 확인 방법과 한계

- 기능 목록은 JSP 54개와 서블릿 명령 7개를 전수로 대조해 만들었다. 화면 디자인·문구는 대상에서 뺐다.
- [실행] 표기는 `asis-runtime/`(Docker Compose, Tomcat 10.1 + MySQL 8.0) 재현 결과다. 재현 환경은 앱 코드를 바꾸지 않았고, Linux에서 돌리기 위해 MySQL 설정 두 가지(`lower_case_table_names=1`, `mysql_native_password`)만 맞췄다.
- 성능·부하는 측정하지 않았다. 데이터가 시드 수준이라 실행계획 비교는 이관 후 측정 단계에서 한다.
